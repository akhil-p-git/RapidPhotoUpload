# Testing

## Running

```bash
cd apps/backend && ./gradlew test     # backend, ~35 tests
cd apps/web && npx tsc --noEmit       # frontend type check
```

No JDK on the machine? The suite runs in a container:

```bash
docker run --rm -v "$PWD/apps/backend":/app -w /app \
  -v "$HOME/.gradle-docker":/gradle -e GRADLE_USER_HOME=/gradle \
  --user "$(id -u):$(id -g)" \
  eclipse-temurin:17-jdk-alpine ./gradlew test --no-daemon
```

## State of the suite

35 tests, all passing.

That is worth stating precisely, because until recently **16 of 20 tests could
not run at all**. Every test touching a `Photo` failed with
`Table "PHOTOS" not found`: the entities declare `columnDefinition = "jsonb"`,
a Postgres type H2 does not know, so schema export failed for those tables and
left nothing to query. Only `AuthServiceTest`, which touches no such entity, was
green. The suite reported failures rather than passing silently, but nothing in
the repo said the failures were structural rather than real.

## What is covered

| Area | File | What it pins |
|---|---|---|
| Auth | `AuthServiceTest` | registration, login, duplicate email |
| Photo queries | `PhotoRepositoryTest` | per-user listing, status filter, counts, ownership lookup |
| Gallery API | `PhotoControllerTest` | listing, fetch, delete, 401 when unauthenticated |
| Chunk upload | `ChunkUploadServiceTest` | a chunk stores; unknown photo id rejected |
| Resume | `ChunkResumeTest` | out-of-order arrival, duplicate sends, recovering the outstanding set after a reload, server-derived chunk totals, non-uploaded rows excluded, abandoned uploads reclaimed |
| Content validation | `UploadValidationTest` | format sniffing; ELF, PE, zip and text rejected; short prefixes never pass; SVG stays off the allowlist |
| Presigned upload | `PresignedUploadValidationTest` | every rejection path: oversize, non-positive, disallowed type, over quota, missing object, size mismatch, unrecognised content, wrong format, another user's photo, and quota refund on rejection |

## What is not covered

Be direct about this in an interview rather than being caught by it.

- **No frontend tests at all.** No unit tests, no component tests, no end-to-end
  browser tests. `tsc --noEmit` is the only automated check, and it currently
  reports 16 pre-existing errors from mixing `@types/react-router-dom` v5 with
  `react-router-dom` v6. The production build skips `tsc` entirely.
- **No test for the resume path in the browser.** `ChunkResumeTest` covers the
  server contract that makes resume possible. The client half -- fingerprinting,
  the IndexedDB store, sending only the missing chunks -- is unverified.
- **No test of the mobile app.**
- **Thumbnail and EXIF processing are untested.** Including the null-GPS crash
  noted in [ARCHITECTURE.md](./ARCHITECTURE.md).
- **No load or concurrency test in the suite.** That lives in
  [`scripts/benchmark`](./scripts/benchmark) and is run by hand.

## Fidelity gap: H2 is not Postgres

Tests run against H2 in PostgreSQL compatibility mode, with a domain aliasing
`jsonb` to `TEXT` so the schema can be created at all. Two things follow:

- **`jsonb` behaviour is not exercised.** Columns declared `jsonb` are plain
  text in tests. Nothing that depends on JSON operators would be caught. (In
  fairness, nothing currently does: the `JsonMapConverter` attached to those
  columns returns `null` unconditionally, so the values are never populated in
  production either. That is its own bug.)
- **Flyway migrations do not run.** The test schema is generated by Hibernate
  from the entities, so a migration that disagrees with an entity would pass the
  suite and fail on a real database.

`org.testcontainers:postgresql` is already declared as a test dependency and
unused. Moving the repository and service tests onto a real Postgres container
would close both gaps; it would make the suite require Docker.

## Benchmark

The upload benchmark is not part of `gradlew test` -- it needs a running
backend, an object store and a browser. See
[`scripts/benchmark/README.md`](./scripts/benchmark/README.md), and
[PERFORMANCE.md](./PERFORMANCE.md) for recorded results.

`scripts/benchmark/src/probe-presigned-limits.mjs` is a live check that a
presigned URL actually refuses a body of the wrong size or type. It has been run
against MinIO. Run it against R2 before claiming R2 enforces the same.
